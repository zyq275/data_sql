# 数据通达 · Data-Agent

> 面向企业内部数仓的 **Text-to-SQL 智能数据问答 Agent** —— 用一句话，问出你要的数据。

用户以自然语言提问，系统完成「理解 → 混合检索 → 生成 SQL → 校验 → 执行 → 解释」全链路，
以流式方式返回进度、SQL、结果表格、自然语言解释与图表推荐；支持多轮追问与指代消解、
按角色的表/字段级数据权限治理、批量评测与确定性数据看板，把取数从「天级工单」压缩为
「秒级对话」。

## 项目简介

企业数仓沉淀了大量结构化数据，但业务人员取数存在**三重门槛**：

| 门槛 | 表现 |
|---|---|
| **技能门槛** | 不懂 SQL，取数依赖数据团队，链路长、耗时数天 |
| **口径门槛** | 同一指标（GMV、客单价）在不同需求里算法不一致，结果难以互信 |
| **上下文门槛** | 取数多是"探索式"——先看总体、再下钻、再对比，传统单轮问答承载不了连续追问 |

「数据通达」针对这三重门槛分别给出答案：**自然语言转 SQL** 解决技能门槛，
**统一指标口径 + 结果可解释** 解决口径门槛，**多轮会话 + 指代消解** 解决上下文门槛；
再补上**评测体系**度量效果、**数据权限治理**管住敏感表与字段。

## 功能点

### 1. 智能问答（核心）

输入一句自然语言问题，输出一个完整答案。这是系统的核心链路。

| 能力 | 说明 |
|---|---|
| 自然语言查询 | 如「去年华东区销售额前三的省份」，无需任何 SQL 知识 |
| 关键字抽取 | 从问句中抽取主题、维度、度量、过滤条件与时间范围 |
| 混合检索 | 向量检索 + 全文检索双路召回相关字段、指标与取值 |
| 召回合并与过滤 | 融合两路结果，筛掉与问题无关的表、字段与指标 |
| 上下文补充 | 自动补入当前日期、数据库信息、会话历史与数据权限范围 |
| SQL 生成 | 按真实表结构生成只读 `SELECT`，含正确的 JOIN 与聚合 |
| SQL 校验 | 首关键字白名单 + 危险操作黑名单 + 多语句拦截 + 只读账号 EXPLAIN 预检 |
| SQL 校正 | 执行不通过时带着错误信息重写，最多 3 次；仍失败则返回明确原因 |
| 执行返回 | 在数仓上执行，返回结果集（超上限时明确提示"已截断"） |

**流式反馈**：整轮以 SSE 推送，节点**一个一个**亮起，而不是等全部算完一次性吐出。

| 事件 | 内容 |
|---|---|
| `progress` | 当前节点与状态（start / done） |
| `sql` | 生成的 SQL |
| `result` | 结果列、行、行数、是否截断 |
| `explain` | 自然语言解释 |
| `viz` | 推荐的图表类型与提示 |
| `error` | 业务错误码与消息（只在终态推一次，校正循环中间不推） |
| `done` | 校正次数与最终行数 |

**几个刻意的设计**：

- **空结果不是报错** —— 明确显示"查询成功，但没有匹配的数据"，而不是空白或红色报错；
- **一问一答可查看 SQL** —— 结果区可展开生成的 SQL 原文，看到的是真实表与 JOIN，
  不是凭空编的表名；
- **安全靠机制而非自觉** —— 数仓账号**只有 SELECT 权限**，即使校验被绕过也写不进去；
  执行侧还有会话级 `MAX_EXECUTION_TIME`、结果行数截断与墙钟超时三重限制。

### 2. 多轮会话与指代消解

把「探索式分析」装进对话里：先看总体、再下钻、再对比，不用把每个问题都写完整。

| 能力 | 说明 |
|---|---|
| 连续追问有上下文 | 先问「各季度销售额」，追问「只看华东」——第二轮**受第一轮约束**，不是从头问一遍 |
| 指代消解 | 「那、它、换成、再」等指代被解析为所指的上文对象，补成完整独立问句 |
| 首轮不改写 | 新会话的第一次提问**原样透传**，不会补出历史里根本不存在的条件 |
| 会话管理 | 新建、切换、删除；侧栏会话标题取该会话第一句话 |
| 历史还原 | 切换会话或刷新页面，历史消息逐轮还原（含 SQL、结果表与解释） |
| 会话续存 | 刷新 / 重启后端不丢会话——图状态快照存在 Redis，会话消息在 MySQL |
| 归属隔离 | 会话仅本人可见；越权一律按"资源不存在"返回 **404**，而不是 403 |

> **为什么是 404 不是 403**：403 等于承认"这个 id 确实存在，只是不归你"，
> 那是一条可以被逐个 id 问出来的信息。

### 3. SQL 可解释性与结果可视化

结果可信任的前提是能看懂它从哪来。

| 能力 | 说明 |
|---|---|
| SQL 展示 | 每次回答都附带生成的 SQL 原文 |
| 自然语言解释 | 解释里提到的过滤条件、分组维度、聚合方式与 SQL 实际逻辑**逐条对得上** |
| 图表类型推荐 | 按结果结构自动推荐柱状图 / 折线图 / 饼图 / 表格 |
| 图表渲染 | ECharts 渲染，可手动切换图表类型 |
| CSV 导出 | 带 BOM（中文在 Excel 不乱码），并做公式注入防护 |

**图表推荐规则**（确定性规则，同一份结果永远给同一个推荐）：

| 结果结构 | 推荐 |
|---|---|
| 结果为空 | 不推荐图表，提示"无数据" |
| 单维分组 + 占比型度量 | 饼图 |
| 单维分组 + 单度量，该维是时间 | 折线图 |
| 单维分组 + 单度量，该维是普通维度 | 柱状图 |
| 单度量，维度全部是时间 | 折线图 |
| 其余（多列明细） | 表格 |

> 切换图表类型**不重新提问**——后端只推荐类型，前端按列结构自己分维度与度量，
> 所以切换是纯粹的本地重绘，不会再调一次模型。

### 4. 数据权限治理

按角色控制可访问的表与字段，**两道闸门**：前置裁剪让模型根本看不到未授权的名字，
后置兜底校验拦住模型自己编出来的表名、以及从历史轮次带进来的旧表名。

| 能力 | 说明 |
|---|---|
| 表级 / 字段级授权 | 按角色配置可访问的表与字段 |
| 权限配置管理 | admin 可在界面上增删改，并可查看某角色**实际生效**的范围 |
| 立即生效 | 配完下一句提问就走新配置，**没有"改完要清缓存"这一步** |
| 不设限要显式说明 | 未配置过任何记录的角色显示为"不设限"，而不是显示成"什么都没有" |
| 越权提示不点名 | 给用户的报错里**不出现表名 / 字段名**——点名等于向无权者确认那张表存在 |

**几条容易配错的规则，都在系统里明确处理了**：

- **未配置 = 不设限**。全新环境里权限表是空的，按白名单严格解读会让所有人都问不出
  任何一张表。一旦某角色有了哪怕一条记录，才按白名单严格执行 ——
  **"开始配置"这个动作本身就是开关**；反过来，删掉某角色最后一条配置 = 退回不设限；
- **一个字段级授权会让整张表按字段级收窄**，于是"先授整表、再收窄到几列"才表达得出来；
  只有表级授权时视为整表可用（含以后新增的字段）；
- **指标按它关联的字段判可见**（口径里写着 `SUM(某字段)`，它本身就是说明书）。

### 5. 查询历史

每次提问都留痕，可回溯、可筛选、可清理。

| 能力 | 说明 |
|---|---|
| 历史列表 | 分页展示，总数正确 |
| 按状态筛选 | 成功 / 失败 / 超时等 |
| 按关键词筛选 | 在问题文本上搜索 |
| 详情 | 含问题 / SQL / 结果预览 / 解释 / 耗时 / 状态六项 |
| 删除 | 删一条，刷新后也不在 |
| 仅本人可见 | 看不到别人的记录 |

### 6. 数据看板

面向 **analyst 及以上**的固定报表页：选维度与指标，直接出图看趋势。

| 能力 | 说明 |
|---|---|
| 维度与指标清单 | 下拉框列出可用的业务维度与指标 |
| 聚合取数 | 按指标口径拼装取数 SQL，出图 / 出表 |
| 趋势 | 选时间维度（年 / 季 / 月）看趋势 |
| 权限裁剪 | 只使用授权范围内的表与字段；被裁剪时有明确提示，不是静默少数据 |
| 角色门槛 | viewer 侧栏无入口、手输地址落到 403 页、直连接口返回 403 |

**看板取数是确定性的，不走模型**：同一个问题两次刷新必须是同一个数，所以这里做的是
**模板填空**——聚合表达式、过滤谓词、维度都来自知识库与代码白名单，刷新多少次都一样。

> **为什么过滤谓词要单独存一份**：指标口径里「GMV 只算已支付订单」正是最要紧的那半句，
> 缺了它会把已取消、已退款的订单一起算进去——数字看着正常，只是偏大。
> 看板与问答报出来的数不一样时，没有人能说清哪个对，所以加了结构化的过滤谓词列，
> 构建时校验、与散文口径必须一致。

### 7. 评测体系

面向 **admin** 的效果度量，把"这次改动到底有没有变好"变成可回答的问题。

| 能力 | 说明 |
|---|---|
| 评测集管理 | 批量导入（单批上限 500 条）/ 删除；重复问题返回 400 |
| 发起评测 | 一条命令跑一批样本，立刻返回，客户端轮询进度 |
| 四个指标 | **准确率 / 召回命中率 / 执行成功率 / 平均耗时** |
| 逐条明细 | 每条样本判对还是判错，可回溯 |
| 趋势看板 | 多次运行的历史趋势，最新的在最前 |
| 不污染线上数据 | 评测运行**不写**会话 / 消息 / 查询历史 / Redis 线程 |

**判分口径：以结果集为准，不比 SQL 文本。** 同一份意图可以有无数种写法（别名、
JOIN 顺序、括号），文本不同不等于结果不同；用文本判会把正确答案判成错的。比对是
顺序无关的多重集比较，列名只用来对齐、不用来判等。

**隔离靠"没有会话"，不靠"记得别写"**：评测用的查询服务在代码里就没有可写的库会话，
于是那四样数据在结构上就不可能被写。换成"用一个真会话、但要小心地不 commit"，
隔离就从结构问题变成了纪律问题，早晚会破。

### 9. 认证与账号

| 能力 | 说明 |
|---|---|
| 登录 | 用户名 + 密码，返回 access / refresh 双令牌 |
| 令牌刷新 | access 令牌过期时自动续期并重放原请求，用户无感 |
| 角色访问控制 | viewer / analyst / admin 三档，前后端双重把关 |
| 当前用户 | `/auth/me` 返回当前身份 |
| 修改密码 | 改完旧密码失效、新密码可登录 |
| 个人设置 | 展示当前用户信息 |

**安全细节**：密码以 bcrypt（`$2b$`）哈希存储，不是明文；登录失败**不区分**是用户名错
还是密码错；日志中不出现明文口令；JWT 密钥未配置时服务**拒绝启动**，而不是等到第一次
登录才 500。

### 10. 元数据知识库

系统"认识"数仓的方式：把表、字段、指标、取值构建成可检索的知识库。

| 能力 | 说明 |
|---|---|
| 声明式定义 | 知识库由 YAML 声明，扩展元数据只改配置，**不改代码** |
| 向量索引 | 字段与指标建立向量索引（Qdrant），支持语义召回 |
| 全文索引 | 字段、指标、取值建立全文索引（Elasticsearch + IK 中文分词） |
| 全量重建 | 一条命令重建 MySQL + 向量 + 全文三处，重建后 id 不变（权限配置不会失效） |
| 入库自检 | 构建末尾核对"配置声明"与"实际入库"的行数，不一致直接失败 |

### 11. 可观测性

| 能力 | 说明 |
|---|---|
| 请求贯穿 | 每个请求一个 `request_id`，贯穿全部日志并写入响应头 `X-Request-Id` |
| 分布式链路 | OpenTelemetry 链路，节点、LLM 调用、召回命中数都在同一棵 trace 树下 |
| Langfuse 追踪 | 每次 LLM 调用一条 generation（带模型名与 token 用量），节点耗时与召回指标可统计 |
| 失败也记录 | 失败请求的耗时与 token 同样是成本，照样上报——只记成功的话，面板上的平均耗时永远是好消息 |
| 内容默认不出境 | 默认只上报结构信息，业务问题原文、SQL 与查询结果**一个字节都不上报** |

> 追踪服务是**可选依赖**：没配也行——request_id、节点耗时、召回命中数的埋点与日志
> 都在应用内，只是 span 没有地方导出。

## 用户角色

| 角色 | 标识 | 权限范围 |
|---|---|---|
| 查看者 | `viewer` | 查询数据、多轮会话、查看本人历史 |
| 分析师 | `analyst` | 查看者权限 + **数据看板** |

## 技术架构

```
                    ┌──────────── 前端 Vue 3 + TypeScript ───────────┐
                    │  登录 / 问答 / 历史 / 看板 / 评测 / 用户与权限   │
                    └──────────────────────┬─────────────────────────┘
                                 REST + SSE │
┌──────────────────────────────────────────▼──────────────────────────────────┐
│  接口层  FastAPI —— 认证 / 会话 / 问答(SSE) / 历史 / 管理 / 权限 / 评测 / 看板 │
├─────────────────────────────────────────────────────────────────────────────┤
│  智能体层  LangGraph —— 指代消解 → 关键字抽取 → 混合检索 → 召回合并与过滤     │
│                        → 上下文补充 → SQL 生成 → 校验 → 校正 → 执行           │
│                        → 解释生成 → 可视化推荐                                │
├─────────────────────────────────────────────────────────────────────────────┤
│  检索层  向量检索(Qdrant) + 全文检索(ES/IK) → RRF 融合 → 精排(Rerank)         │
├─────────────────────────────────────────────────────────────────────────────┤
│  存储层  MySQL(元数据 + 数仓) │ Qdrant(向量) │ ES(全文) │ Redis(会话状态)      │
├─────────────────────────────────────────────────────────────────────────────┤
│  可观测层  日志(request_id) / OpenTelemetry 链路 / Langfuse 追踪              │
└─────────────────────────────────────────────────────────────────────────────┘
```

**一次提问实际发生的事**：

```
自然语言问题
   │
   ├─ 有上文？→ 指代消解，把"只看华东"补成完整问句
   ├─ 关键字抽取 ─┬─ 字段召回（向量 + 全文）
   │              ├─ 取值召回（全文）
   │              └─ 指标召回（向量 + 全文）      ← 三路并行，RRF 融合后精排
   ├─ 召回合并 → 筛表 → 筛指标 → 补上下文（日期/库信息/历史/权限）
   ├─ 生成 SQL → 只读校验 → 不通过则带着错误重写（最多 3 次）
   ├─ 执行（只读账号 + EXPLAIN 预检 + 超时与行数限制）
   └─ 生成自然语言解释 → 推荐图表类型 → 推 done
```

## 快速开始

完整步骤见 [data-agent/README.md](data-agent/README.md)（后端）与
[data-agent-frontend/README.md](data-agent-frontend/README.md)（前端）。最小流程：

```bash
# 1. 后端依赖与配置
cd data-agent
uv venv --python 3.12 && uv pip install -e .
cp .env.example .env             # 填入数据库口令、LLM__API_KEY、JWT__SECRET_KEY

# 2. 建库、迁移、造样例数据、初始化管理员
.venv/Scripts/python.exe -m alembic upgrade head
DW_READONLY_PASSWORD='<口令>' .venv/Scripts/python.exe -m app.scripts.seed_dw --create-account
.venv/Scripts/python.exe -m app.scripts.seed_dw
.venv/Scripts/python.exe -m app.scripts.build_meta
ADMIN_PASSWORD='<口令>' .venv/Scripts/python.exe -m app.scripts.init_admin --username admin

# 3. 起后端（http://127.0.0.1:8000）
.venv/Scripts/python.exe -m uvicorn main:app --reload

# 4. 起前端（http://localhost:5173）
cd ../data-agent-frontend && npm install && npm run dev
```

**外部依赖**：MySQL 8、Qdrant、Elasticsearch 8 + ik、Embedding 服务（Ollama bge-m3）、
大模型服务（OpenAI 兼容端点）。Rerank 服务、Redis、Langfuse 均为可选。
每项的安装与配置见 [data-agent/README.md](data-agent/README.md#依赖服务)。
